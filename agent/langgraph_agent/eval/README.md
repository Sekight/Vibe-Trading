# P0-2 评测语料（量化原生）

> 45 条：40 条单意图 + 5 条多意图。全部为量化研究请求，不含任何 HR/简历/岗位内容。

## 为什么是这套语料

P0-2 要证明的是「状态图能把一条消息里的多个意图拆开并逐个执行」。这需要一批**有明确动作标注**的请求。vibe-trading 没有现成的动作标注集，所以这里按项目真实工具（`get_market_data` / `backtest` / `write_run_analysis`）设计了一套小规模合成语料。

**不使用 ai-job 的 HR 语料**：那是另一个项目（单步、不可逆动作）的评测集，搬到量化项目里会造成领域错位，面试叙事也立不住。

## 规模与分布

| 类型 | 条数 | 期望动作 | 说明 |
|---|---:|---|---|
| `market_data` | 8 | `MARKET_DATA` | 只要行情/K 线 |
| `backtest` | 8 | `BACKTEST` | 明确要跑策略回测 |
| `report` | 8 | `REPORT` | 要对已有回测出报告/归因/解释 |
| `clarify` | 8 | `CLARIFY` | 缺标的、缺日期或缺策略 |
| `stop` | 8 | `STOP` | 致谢/结束/无关闲聊 |
| `multi_intent` | 5 | 2-3 个动作 | 一条消息多个明确意图 |

## 标注规则

1. **动作集完全一致**才算 pass；多意图另报覆盖率（recall）。
2. `clarify` 只在“缺标的 / 缺日期 / 缺策略”三者至少缺一时才标；不缺参数却标 clarify 算错。
3. `stop` 不允许触发任何工具；`market_data`/`backtest`/`report` 不允许越界到别的动作。
4. 多意图的期望动作按**用户显式说出的意图**标注，不把内部依赖（回测需要取数）算成额外动作。
5. 每个 case 的 `notes` 写清标注理由；`reviewed: true` 表示人工核对过。
6. 新增 case 后必须跑：

```powershell
cd agent
..\.venv\Scripts\python.exe -m langgraph_agent.run_eval --check-data
```

校验项：id 唯一、动作在枚举内、单意图 40 / 多意图 5、无 HR 词表残留。

## 已知边界

- 合成句、单轮、单模型；不能代表真实用户分布。
- 日期/标的都是显式的；真实场景里的相对时间（“最近一年”）需要另一套时间解析评测，不在本版范围。
- 评测用 stub 工具，不验证回测结果正确性；真实链路见 `live_demo.py`。
