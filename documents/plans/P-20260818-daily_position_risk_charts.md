## 项目调研

- 分析图链路：`GET /runs/{id}/analysis/charts`（`agent/src/api/runs_routes.py`，已有 run_dir）→ `load_digest(run_dir)` → `compute_chart_payload(digest)`（`agent/backtest/analysis/charts.py`，从 digest 的 equity/trades/monthly_pnl/buckets 字段构建 ECharts 点数组）→ 前端 `AnalysisChartsTab`（`frontend/src/pages/RunDetail.tsx`）按 `ANALYSIS_CHART_ORDER` 渲染卡片。加图 = digest/charts payload 加字段 + 前端加卡片。
- 数据可用性（v438/v43fix 产物实测）：`artifacts/positions.csv` 每 bar 每 code 目标权重（带符号，6942 bar）；`artifacts/equity.csv` 每 bar 总权益。digest 目前**不含持仓权重序列**，需新增读取。
- 账户风险度行业规则（百度知道/和讯/证监会表述/叩富网，多来源交叉验证）：
  - 公式：**风险度 = 占用保证金 ÷ 客户权益 × 100%**；保证金 = 合约价值 × 保证金比例。
  - 客户权益 = 账户总资产（期初资金 + 平仓盈亏 + 持仓浮动盈亏 − 手续费），**浮盈浮亏含在分母权益里**，不是加在分子保证金上。
  - 强平线：证监会表述"权益触及或低于所需保证金水平时强平，直至风险率 ≤ 100%"（100% = 权益=保证金、可用资金=0）；风险度 > 100% 发《追加保证金通知书》；各公司实际风控线 100%~120% 不等。
- 引擎保证金推导（`base.py`）：`margin = size×price÷leverage`（744-752），`size = |w|×equity×leverage÷price`（1391-1394），两式相乘**杠杆抵消** → 开仓时 `margin = |w|×equity`。持仓期间引擎**不每天调仓**（`_execute_bars` 只在 target 为空/方向改变时平仓 1352-1353、只在无持仓时开仓 1136），`size` 固定、`margin` 按**开仓价**计算（1276 `pos.entry_price`），`equity = capital + margin + 浮动盈亏` 随行情波动 → **风险度 = margin/equity 随浮亏被动上升，与真实期货行为一致**。
- 目标权重来源：**策略代码** `signal_engine.py` 的 `generate()` 返回每日权重序列（v43fix 已核实：持仓期间权重恒定为开仓时 w，202/276 行）；**config.json 无任何权重/leverage 配置**（v43fix config 已核实）。
- 性能实测（10 年 ≈ 2400 交易日 × 100 标的）：组合毛持仓单条线 2400 点 ≈ 96 KB；100 标的全序列 24 万点 ≈ 8.9 MB（传输+渲染会卡）；每天最大单标的单条线 ≈ 91 KB。后端 pandas 聚合 24 万格子秒级，瓶颈只在前端传输/渲染。
- 现有测试：`test_analysis_charts.py`（payload 字段）、`test_analysis_digest.py`；`compute_chart_payload` 签名变化会波及 runs_routes.py / runner / 测试。

## 实现方案

0. **digest 决策（已调研）**：持仓/风险序列**写入 digest**（全量时序），LLM 只渲染**派生摘要**。依据：
   - 耗时实测：读 positions.csv + 聚合 2433 天三口径 **148ms**、JSON 序列化 ~1.6ms、写盘增量 **156KB**——相对 digest 构建（fastrun 1.1s / 完整版 750s）可忽略，**不纳入 fastrun 跳表**（轻量常驻）；
   - LLM 已有**标量**仓位指标（`avg/max_portfolio_weight`、`max_single_weight`、`risk_xray_avg_invested` 等，digest `metrics` 字段，render_digest_for_llm"指标解读"分组可见），**无时序**；全量时序（2433 点）直接渲染会撑爆 token，故 LLM 只给摘要（毛持仓/风险度 max、avg、超 50%/80%/100% 天数等）；
   - 架构一致性：现有所有图表从 digest 取（`compute_chart_payload(digest)`），序列进 digest 则**签名不变**、图表/PNG/LLM 单点同源；不进 digest 需改签名 + 多数据源（不推荐）。
1. **digest.py**：
   - `build_digest` 读 `artifacts/positions.csv`，按交易日聚合三口径（毛 `sum|w|` / 净 `sum w` / 单边=按 `weight_groups` 分组取多空大边后求和），日取峰值 → 新增 `daily_position`（[{date, gross, net, single}]，百分比）；
   - 账户风险度 = 单边口径 ÷ 权益（引擎 `margin=sum(单边)×equity`，权益=equity.csv 当日值；`risk_pct = single_pct`，因引擎保证金恒=|w|×equity）→ 新增 `daily_risk`（[{date, risk_pct}]，含 100% 参考线数据）；
   - `render_digest_for_llm` 新增「仓位与风险摘要」段：毛持仓/风险度 max、avg、超 50%/80%/100% 的天数与占比、最高区间（**不渲染全量时序**）。
2. **charts.py**：`compute_chart_payload` 透传 `daily_position` / `daily_risk` 两个新 key（从 digest 取，签名不变）；**不加** CHART_SPECS（新 tab 不做 PNG）。
3. **前端 RunDetail.tsx**：
   - `Tab` 类型加新 tab（如 `"positions"`），按钮位于 `analysisCharts`（分析图）与 `analysis`（分析）之间；
   - 新增 `PositionsRiskTab` 组件（调 `api.getRunAnalysisCharts` 复用 charts 数据）：图 1 毛持仓默认单线 + 图例开关叠加净/单边（ECharts legend selected 控制）；图 2 风险度折线 + `markLine` 100% 参考线 + 超线点标红；
   - 5 语言包 i18n 文案（tab 名、图标题、图例、说明"日取峰值"）。
4. **测试**：后端（构造小 positions.csv 断言三口径日聚合正确、`daily_risk` 计算、空仓/单标的不崩、LLM 摘要段渲染不撑爆）；前端组件测试可选。
5. **文档**：HowToUse 8.36（新增 tab 说明）+ 8.45 或并入（风险度口径、毛/净/单边区别、开仓价 vs 结算价、引擎全额占用差异、二期可迭代点）；ITERATION_LOG；计划收尾。

## 风险 / 注意

- **二期可迭代点（已记录，写进迭代日志）**：逐标的持仓展示 + 下拉框按需加载——组合级序列（2400 点 ~96KB）可进 digest；**全标的逐标的序列（100 标的 × 2400 天 ≈ 24 万点 8.9MB）不得进 digest**（拖慢所有消费方），二期必须 API 现读 positions.csv 按需返回单标的序列。
- 口径选择影响图 2 语义：毛口径在锁仓策略下高估真实保证金（保守）；单边口径最贴真实期货。TA 恒同向三口径无差异。
- 引擎保证金按开仓价、真实期货按结算价：风险度曲线平滑度差异，需 HowToUse 注明；引擎执行模型逐 code 全额占用保证金（资金约束保守），与展示的单边口径是两回事。
- 空头日带符号求和为负：聚合必须用绝对值/毛口径（v438 2014-01-09 实测 -0.2177）。
- digest 增 156KB（全量时序）：load_digest/写盘略有增加，已实测可接受；LLM 渲染**只出摘要**防 token 爆炸。
- 新 tab 布局：位于 `analysisCharts` 与 `analysis` 之间，改前端 Tab 类型与按钮顺序，注意现有 tab 状态持久化逻辑。
- `compute_chart_payload` 签名不变（序列走 digest），不影响 runs_routes.py / runner / 现有测试。
