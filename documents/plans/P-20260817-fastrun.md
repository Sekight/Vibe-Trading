## 项目调研

- 3 年 5m 回测缓存命中总耗时 766s，其中回测后 digest（分析数据生成）约 750s 占 98%（引擎执行仅 ~14s）；1 个月 5m 全程 16s（2026-08-17 实测，见全局 E010 / Mistake_Journal M027）。
- digest 慢的两个组件（cProfile 定位）：`compute_edge_density`（agent/backtest/regime.py，每个 bar 做一次 60-bar 窗口滚动 pandas corr，O(bar×window)）与 `add_mae_mfe`（agent/backtest/analysis/digest.py，每笔交易遍历该标的全量 bar 筛窗口，O(trades×bars)）。
- digest 消费方：WebUI 分析图/分析标签从 `analysis.digest.json` 取数；相关性 regime 另有独立端点 `/correlation/regime`（system_routes.py，与本需求无关，不动）。前端组件 RegimeTimeline.tsx / 分析图图表读取 digest 字段（2026-08-17 初步 grep，缺失容错点为执行清单第 1 步）。

## 需求目标

- 做什么：给直接跑回测的入口 `python -m backtest.runner <run_dir>` 增加三个指令（CLI flag），控制回测后 digest 的计算内容：
  - `--without-regime`：不计算相关性 regime 分析（edge density / FUSED 状态机），digest 省略对应字段与 markdown 段落；
  - `--without-mae-mfe`：不计算 MAE/MFE（逐笔 bar 级极值），digest 省略对应字段；
  - `--fastrun`：以上两个都不输出（等价组合开关），且设计为**可扩展**——以"跳表/集合"形式实现，以后发现 digest 或其他阶段有耗时步骤，直接追加进 fastrun 跳表即可，一切为了尽快跑出回测与核心指标（metrics.csv / trades.csv / run_card）。
- 范围 / 边界：
  - 只改回测 runner 与 digest 构建（agent/backtest/runner.py、agent/backtest/analysis/digest.py）及其消费方容错；**不动引擎执行、不动 metrics 核心指标、不动 trades.csv/equity.csv 产物**。
  - 独立端点 `/correlation/regime` 不纳入；WebUI 交互页面的指标卡/交易表/图表主图不因跳过而变化（只有依赖被跳字段的分析图/分析报告部分降级）。
  - 默认行为不变：不加 flag 时 digest 与现状完全一致。
  - config.json 不新增字段（纯 CLI flag）；`--fastrun` 与两个独立 flag 可组合使用（如 `--fastrun` 已含全部，再显式传独立 flag 不报错）。
  - `--fastrun`（或带独立 flag）重跑会**覆盖**该 run 已有 digest 为精简版：该 run 在 WebUI 的 MAE/MFE 分析图与 LLM 报告的 Regime 段随之降级，直到完整重跑才恢复（已拍板接受，见讨论记录 2026-08-17）。
- 验收标准：
  - **digest 字段级对比**（核心）：同一 run 目录完整跑 vs `--fastrun` 跑，两份 `analysis.digest.json` 的 `digest` 对象在排除 `generated_at`、`trades[].mae_pct/mfe_pct`、`regime`、`mae_mfe_summary` 后，其余字段（metrics / equity / monthly_pnl / period_pnl / buckets / top_winners / top_losers / trade_summary / ohlcv_summary / reproducibility）逐字段一致（diff 为空）——证明只跳了该跳的，没误伤其他数据。
  - **默认行为零变化**：不加 flag 时，`build_digest` / `write_digest_json` / `load_digest` 输出与改动前逐字节一致（synthetic run 前后对比，排除 `generated_at` 后 sha256 一致）。
  - **消费方不崩**：digest 缺 regime/mae_mfe 字段时，`render_digest_for_llm` 不输出这两段且不抛异常；`compute_chart_payload["mae_mfe"] == []` 且其他 key 与完整版一致；`--with-charts` PNG 生成不崩；WebUI 分析图 tab 正常降级（mae_mfe 卡片显示占位标注，见实现方案 3）。
  - **性能**：`--fastrun` 跑 3 年 5m 总耗时从 766s 降到 1 分钟内（预期主要剩 fetch/generate/run_backtest ~18s + 精简 digest）；单独 `--without-regime` 与 `--without-mae-mfe` 各计时，确认各自贡献占比。

## 实现方案

（涉及文件/模块、关键设计；讨论中随时补充）

1. **digest.py**：
   - `build_digest(run_dir, *, include_regime=True, include_mae_mfe=True)`——`include_regime=False` 时跳过 `_regime_from_run(...)` 调用且 digest **不含 `regime` key**；`include_mae_mfe=False` 时 trades 直接 `pair_trades(raw_trades)`（不加 `add_mae_mfe`）、digest **不含 `mae_mfe_summary` key**（注意：`mae_mfe_summary` 现在是恒有 key，改为按 include 条件输出，跳过时 key 整体省略）。
   - `write_digest_json(run_dir, digest=None, *, include_regime=True, include_mae_mfe=True)`——**digest=None 时按 include 参数 build**（runner 的调用点正是 `write_digest_json(run_dir)`，必须透传，否则 flag 传不进去）。
   - `render_digest_for_llm`——regime 段与 MAE/MFE 段改为**条件渲染**：`"regime" in digest` 才输出 "## Regime 摘要" 段、`"mae_mfe_summary" in digest` 才输出 "## MAE/MFE" 段（key 缺失即整段跳过，不输出 "-" 占位）。完整版 key 恒在，渲染与现状完全一致。
2. **runner.py**：
   - `__main__` 增加 `--without-regime` / `--without-mae-mfe` / `--fastrun` 三个 argparse flag；构建 skip 集合 `skips: set[str]`（`--fastrun` 预置 `FASTRUN_SKIPS = {"regime", "mae_mfe"}` 模块级常量，后续新耗时步骤直接追加此集合即可）。
   - `main(run_dir, with_analysis, with_charts, *, without_regime=False, without_mae_mfe=False)` 与 `_finalize_run_analysis(...)` 各加两个关键字参数透传；`_finalize_run_analysis` 内 `write_digest_json(run_dir, include_regime=not without_regime, include_mae_mfe=not without_mae_mfe)`。
   - 边界：MCP `backtest_tool` 子进程不传 flag（不透传，已拍板）——agent 工具路径仍跑完整 digest，本次范围只覆盖 CLI。
3. **消费方**（执行清单第 1 步调研结论：后端现状已容错，唯一需要改的是前端）：
   - 后端 `compute_chart_payload`：fastrun digest 下 `mae_mfe` 点列表为空（`trade.get("mae_pct") is None` 被过滤），PNG `_render_mae_mfe` 渲染空坐标轴不崩——**无需改动**。
   - 前端 `RunDetail.tsx` AnalysisChartsTab：mae_mfe 卡片在 `payload.mae_mfe` 为空数组时**不渲染空散点图**，改显示占位标注（文案涵盖两种情况："该 run 未计算 MAE/MFE（fastrun 模式或无可分析窗口）"）——已拍板采用后者。主图/指标卡/交易表不读 digest，不受影响。
4. 文档：HowToUse 8.38（回测提速段）补充 fastrun 三个 flag 的说明与实测耗时对比，并写明"fastrun 重跑会覆盖该 run 的 digest，MAE/MFE 图与报告 Regime 段降级，完整重跑可恢复"。

## 讨论记录

（append-only：谁提出、选项、结论；范围/边界反转时标注"范围变更：原=... → 现=..."）

- 2026-08-17 用户提出：对跑回测加 3 个指令（without regime / without MAE-MFE / fastrun），fastrun 定位为"以后发现哪步耗时就把那步也纳入 fastrun"，一切为尽快跑出 metric。
- 2026-08-17 代码评估（Codex/ZCode）：瓶颈定位与调用链核实属实；发现 3 处计划缺口——①`write_digest_json` 内部无参调 `build_digest`，必须加 include 参数透传；②`render_digest_for_llm` 缺 key 时会渲染 "-" 误导占位，需改条件渲染整段跳过；③`load_digest` 惰性重建路径（digest 文件缺失/指纹变化）会无参完整重建，fastrun 加速只对指纹匹配的读取生效。另核实：前端 RunDetail 不读 digest.regime（RegimeTimeline 只服务独立 API）；`ui_services` 主图/指标卡/交易表不读 digest；MCP backtest_tool 子进程无 flag（agent 路径拿不到 fastrun）。
- 2026-08-17 用户拍板：
  1. `--fastrun` 重跑覆盖既有完整 digest（接受，分析图降级可完整重跑恢复）；
  2. 前端 mae_mfe 空数据：采用"隐藏空图 + 占位标注"（不渲染空散点图）；
  3. `load_digest` 惰性重建：不写 digest 标记，重建=完整 digest（数据完整优先，重建耗时属预期）；
  4. MCP backtest_tool 不透传 flag，本次范围只覆盖 CLI。

## 风险 / 注意

- digest 缺失字段的兼容：旧 run 的完整 digest 不受影响；fastrun 产生的 digest 被消费方读取时按"key 缺失整段跳过/空图占位"处理（已核实后端现状均容错，前端补占位）。
- `load_digest` 惰性重建：digest 文件缺失或 artifacts 指纹变化时，charts/report/API 会**无参完整重建**（不写 fastrun 标记，已拍板），3 年 5m 下约 750s 复现——属预期行为，非 bug。
- `--fastrun` 重跑覆盖已有完整 digest（已拍板接受）；HowToUse 写明"完整重跑可恢复"。
- MCP backtest_tool 不透传 flag（已拍板）：agent 工具路径仍跑完整 digest。
- `--fastrun` 只是跳过分析，不改变回测与指标口径；MAE/MFE 图、regime 时间线在 fastrun run 中不可见属预期。
- 单标的 run 本就不产生有意义的 regime（需 ≥2 标的），`--without-regime` 对这类 run 无额外收益但也不报错。
- regime 分析基于日期对齐的 close（`_load_close_prices` 用日期前缀），对子日数据（5m 等）存在重复日期 index，结果有效性存疑（非本次改动引入，现状行为）；性能上 3 年 5m 单标的 run 的 regime 本就 skipped（cheap），主头大概率是 add_mae_mfe。
